# RED Virt Analytics

RED Virt Analytics — локальный дашборд для диагностики баз данных oVirt Engine. Инструмент предназначен для инженеров L2/L3 технической поддержки РЕД СОФТ и позволяет анализировать восстановленные дампы PostgreSQL без подключения к продуктивной среде.

## Возможности

- анализ хостов, виртуальных машин, кластеров, сетей и хранилищ;
- диагностика дисков, образов и цепочек снапшотов;
- просмотр задач, событий, пользователей, прав и сертификатов;
- инспекторы объектов с подробными диагностическими отчётами;
- фильтрация по дата-центрам, кластерам и хостам;
- цветовая индикация состояния объектов;
- просмотр системных таблиц и выполнение SQL-запросов только на чтение;
- экспорт результатов в CSV;
- запуск в Docker без установки Python на рабочую станцию.

## Требования

Для первого запуска необходимы:

1. **Docker и Docker Compose** — [РЕД ОС 8](docs/DOCKER_RED_OS.md), [Windows](docs/DOCKER_WINDOWS.md).
2. **PostgreSQL с восстановленным дампом oVirt Engine** — [ДОБАВИТЬ ССЫЛКУ НА ИНСТРУКЦИЮ ПО УСТАНОВКЕ И ВОССТАНОВЛЕНИЮ ДАМПА].
3. Распакованный архив RED Virt Analytics.

Поддерживаемые рабочие станции:

- РЕД ОС 8;
- Windows с установленным Docker Desktop.

## Быстрый запуск

### 1. Подготовьте базу данных

Установите PostgreSQL и восстановите в него дамп oVirt Engine.

Подробная инструкция: [ДОБАВИТЬ ССЫЛКУ НА СТАТЬЮ]. Запуск приложения после восстановления дампа описан в [руководстве администратора](docs/ADMIN_GUIDE.md).

Приложение предназначено для анализа локально восстановленной копии базы данных. Не подключайте его напрямую к продуктивной базе oVirt Engine.

### 2. Распакуйте архив

Распакуйте архив приложения в отдельный каталог. Путь к каталогу не должен содержать недоступных текущему пользователю директорий.

### 3. Запустите установку

Откройте терминал в каталоге приложения и выполните команду для своей операционной системы.

**Linux:**

```bash
./start.sh
```

Если файл не разрешено выполнять:

```bash
chmod +x start.sh
./start.sh
```

**Windows:**

```cmd
start.bat
```

При первом запуске скрипт запросит параметры подключения и соберёт Docker-контейнер.

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `DB_HOST` | `host.docker.internal` | PostgreSQL находится на той же машине, что и Docker |
| `DB_PORT` | `5432` | Порт PostgreSQL |
| `DB_NAME` | `engine` | Имя базы данных с восстановленным дампом |
| `DB_USER` | `postgres` | Пользователь PostgreSQL |
| `DB_PASSWORD` | — | Пароль пользователя PostgreSQL, обязателен |

### 4. Откройте приложение

После успешного запуска откройте в браузере:

**http://localhost:8502**

Приложение доступно только с локального компьютера. Порт дашборда не публикуется в локальную сеть. Экземпляр рассчитан на одного инженера на рабочей станции: история SQL-редактора общая для всех вкладок этого запуска.

## Управление приложением

### Linux

```bash
./start.sh              # Запустить или пересобрать приложение
./start.sh -r           # Повторно настроить подключение к PostgreSQL
docker compose down     # Остановить приложение
docker compose logs -f  # Просматривать журналы контейнера
```

### Windows

```cmd
start.bat               :: Запустить или пересобрать приложение
start.bat -r            :: Повторно настроить подключение к PostgreSQL
docker compose down     :: Остановить приложение
docker compose logs -f  :: Просматривать журналы контейнера
```

## Безопасность и ограничения

- Дампы oVirt Engine могут содержать имена пользователей, адреса узлов и другие конфиденциальные сведения. Храните их в защищённом месте.
- Дашборд должен работать с локально восстановленной копией базы данных, а не с продуктивным Engine.
- Подключения приложения открываются в режиме `read-only` с ограничением времени выполнения SQL-запросов.
- SQL-редактор разрешает только запросы на чтение и ограничивает количество возвращаемых строк.
- Доступ к интерфейсу по умолчанию разрешён только через `127.0.0.1:8502`.
