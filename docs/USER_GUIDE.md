# Руководство пользователя RED Virt Analytics

## 1. Назначение

RED Virt Analytics предназначен для анализа локально восстановленных дампов базы данных oVirt Engine. Приложение помогает инженеру технической поддержки находить проблемные объекты, проверять связи между компонентами инфраструктуры и формировать диагностические отчёты.

Приложение работает только на чтение и не предназначено для изменения данных Engine.

Установка, настройка подключения и устранение проблем запуска описаны в [руководстве администратора](ADMIN_GUIDE.md).

## 2. Открытие приложения

После запуска откройте в браузере:

**http://localhost:8502**

В боковой панели указана версия приложения.

Если страница недоступна, обратитесь к разделу [«Устранение проблем»](ADMIN_GUIDE.md#13-устранение-проблем) в руководстве администратора.

## 3. Выбор базы данных

В верхней части боковой панели находится переключатель **«База для анализа»**. В нём отображаются базы данных PostgreSQL, доступные указанному при установке пользователю.

1. Выберите базу с восстановленным дампом.
2. Дождитесь загрузки структуры инфраструктуры.
3. Убедитесь, что под переключателем указано правильное имя текущей базы.

При смене базы приложение сбрасывает загруженные метаданные и повторно читает структуру выбранного дампа.

> Не выбирайте продуктивную базу oVirt Engine. Приложение должно использоваться с локально восстановленной копией.

## 5. Общие принципы работы

### Фильтры

Большинство разделов поддерживает:

- фильтрацию по состоянию объекта;
- выбор дата-центра;
- выбор кластера;
- выбор хоста;
- поиск по имени, UUID, FQDN или другому идентификатору.

Доступные значения зависимых фильтров изменяются последовательно. Например, после выбора дата-центра в списке кластеров остаются кластеры этого дата-центра.

Если хотя бы один фильтр изменён, появляется кнопка **«Сбросить фильтры»**.

### Цветовая индикация

Цвет используется как вспомогательное обозначение состояния:

- зелёный — штатное состояние;
- оранжевый — состояние требует внимания;
- красный — проблема или критическое состояние;
- серый — нейтральное, неизвестное или неприменимое состояние.

Окончательный вывод следует делать по полям объекта и диагностическому отчёту, а не только по цвету строки.

### Таблицы

Таблицы можно прокручивать, сортировать по столбцам и использовать для выбора объекта. В разделах с инспектором выберите одну строку таблицы — под ней появится подробный отчёт.

Средствами панели таблицы Streamlit результаты можно сохранить в CSV, если эта операция доступна в используемой версии интерфейса.

## 6. Разделы приложения

### 6.1 Хосты

Раздел показывает хосты виртуализации и их состояние.

Доступны:

- фильтры по дата-центру и кластеру;
- поиск по имени хоста или FQDN;
- быстрый отбор `Up`, `Maintenance` и остальных состояний;
- количество активных виртуальных машин;
- признак текущего SPM;
- дата-центр и кластер хоста.

Чтобы открыть **Host Inspector**, выберите строку хоста. Отчёт содержит идентификаторы, состояние, ресурсы, сети, хранилища и связанные события, если эти сведения присутствуют в дампе.

### 6.2 Виртуальные машины

Раздел предназначен для поиска и анализа ВМ.

Доступны:

- каскадные фильтры дата-центр → кластер → хост;
- поиск по имени или UUID;
- отбор `Up`, `Down` и остальных состояний;
- состояние ВМ и её дисковых слоёв;
- отображение текущего хоста, кластера и дата-центра.

Выберите строку, чтобы сформировать **VM Inspector**. В отчёт включаются конфигурация ВМ, диски и слои, сеть, снапшоты, размещение и связанные диагностические сведения.

### 6.3 Снапшоты и слои

Раздел показывает снапшоты ВМ и связанные дисковые слои.

Доступны:

- фильтры по дата-центру и кластеру;
- поиск по имени ВМ, UUID снапшота или UUID слоя;
- отбор штатных и проблемных записей;
- тип и дата создания снапшота;
- размер, хранилище и состояние слоя.

При выборе обычного снапшота формируется **Snapshot Inspector**. Если обнаружен слой без связанного снапшота, приложение формирует отчёт **Disk Inspector** для этого слоя.

### 6.4 Кластеры

Раздел содержит сведения о кластерах, их параметрах и состоянии входящих хостов.

Можно:

- отфильтровать кластеры по дата-центру;
- найти кластер по имени или UUID;
- выделить штатные и проблемные кластеры;
- выбрать кластер и сформировать подробный отчёт.

### 6.5 Сети

Раздел используется для анализа логических сетей и связанных объектов.

Можно:

- отфильтровать сети по дата-центру;
- выполнить поиск по имени или идентификатору;
- посмотреть состояние и назначение сети;
- выбрать сеть для формирования диагностического отчёта;
- просмотреть связанные системные таблицы в диагностическом блоке.

### 6.6 Хранилища

Раздел показывает домены хранения и их связь с дата-центрами.

Можно:

- выбрать дата-центр;
- найти хранилище по имени или UUID;
- отфильтровать объекты по состоянию;
- проверить тип, доступность и состояние домена;
- сформировать отчёт по выбранному хранилищу.

### 6.7 Диски и образы

Раздел предназначен для анализа виртуальных дисков, образов и дисковых слоёв.

Поддерживается поиск по:

- идентификатору или имени диска;
- имени ВМ;
- имени хранилища.

Выбор строки открывает подробный отчёт о диске, его слоях, связанной ВМ и домене хранения.

### 6.8 Gluster

Раздел отображает тома Gluster, брики и связанные службы.

Доступны фильтр по кластеру, поиск, проверка состояний и формирование отчёта по выбранному объекту.

Если в дампе отсутствуют таблицы Gluster, раздел может быть пустым — это не обязательно означает ошибку восстановления.

### 6.9 Задачи

Раздел помогает анализировать асинхронные команды и зависшие операции.

Доступны:

- фильтры по дата-центру, кластеру и хосту;
- поиск по имени ВМ;
- поиск по идентификатору задачи или команды;
- просмотр состояния, результата и времени запуска;
- отображение связанных сущностей и событий.

Выберите задачу, чтобы увидеть её подробности и найденные связи.

### 6.10 Журнал событий

Раздел отображает записи `audit_log`.

Можно:

- ограничить события дата-центром, кластером или хостом;
- выполнить текстовый поиск;
- отфильтровать события по важности;
- выбрать событие и просмотреть его полное содержание.

При работе с большим журналом используйте фильтры: это уменьшает время выполнения запроса и объём отображаемых данных.

### 6.11 Сертификаты

Раздел показывает сведения о сертификатах, найденных в базе данных:

- назначение сертификата;
- владелец или связанный объект;
- даты начала и окончания действия;
- оставшийся срок действия;
- предупреждения об истекающих и недействительных сертификатах.

Наличие данных зависит от версии и состава восстановленного дампа.

### 6.12 Системные

Раздел содержит системную информацию и состоит из вкладок:

- активные сессии;
- настройки fencing;
- квоты;
- трансферы образов.

В верхней части отображается найденный Hosted Engine. Если в инфраструктуре есть хосты, но настройки fencing не обнаружены, приложение показывает предупреждение.

Используйте поиск по имени, IP-адресу или ключу конфигурации.

### 6.13 Пользователи и права

Раздел используется для анализа пользователей, доменов, ролей и назначенных разрешений.

Можно:

- выбрать домен;
- найти пользователя или группу;
- выбрать строку и просмотреть связанные роли и разрешения;
- открыть диагностические таблицы раздела.

### 6.14 Справочник схемы БД

Справочник описывает таблицы и поля Engine DB.

1. Выберите версию схемы.
2. При необходимости выберите группу таблиц.
3. Введите имя таблицы, поля или часть описания.
4. Откройте найденную таблицу для просмотра назначения и состава полей.

Если приложение смогло определить версию Engine по дампу, соответствующая схема выбирается автоматически. В верхней части раздела отображаются сведения об изменениях схемы между поддерживаемыми версиями.

## 7. Диагностические таблицы

Под основным содержимым многих разделов расположен блок просмотра исходных таблиц Engine DB.

Используйте его, когда необходимо:

- проверить данные, на основании которых сформирован отчёт;
- посмотреть дополнительные поля объекта;
- сопоставить сведения из нескольких таблиц;
- подтвердить наличие или отсутствие записи в дампе.

Количество строк ограничивается приложением. Увеличивайте лимит только при необходимости.

## 8. SQL-редактор

SQL-редактор находится в раскрывающемся блоке **«SQL-редактор»** в рабочей области приложения.

Пример запроса:

```sql
SELECT vm_name, vm_guid
FROM vm_static
ORDER BY vm_name
LIMIT 20;
```

### Ограничения редактора

- разрешены только запросы на чтение;
- несколько SQL-выражений в одном запуске запрещены;
- изменение и удаление данных запрещено;
- количество возвращаемых строк ограничивается приложением;
- длительный запрос прерывается по таймауту;
- некоторые команды чтения могут быть недоступны из-за прав пользователя PostgreSQL.

Выполненные запросы сохраняются в истории отдельно для каждой базы. Запрос можно повторно выбрать из списка истории или удалить историю кнопкой с изображением корзины.

Перед выполнением сложного запроса рекомендуется сначала проверить его на небольшой выборке с `LIMIT`.

## 9. Сообщения приложения

### «Данных нет» или «Объекты не найдены»

Это означает, что запрос выполнился успешно, но записи не соответствуют фильтрам либо отсутствуют в дампе. Сбросьте фильтры и повторите поиск.

### Ошибка отсутствующей таблицы или колонки

Структура дампа может отличаться от ожидаемой версии Engine. Проверьте определённую приложением версию в разделе «Системные» и сведения о совместимости в справочнике схемы.

### Запрос прерван по таймауту

Уменьшите диапазон поиска, примените дополнительные фильтры либо упростите SQL-запрос.

### Ошибка подключения

Если ошибка появляется во всех разделах, проверьте доступность PostgreSQL и параметры подключения. Дальнейшие действия описаны в [руководстве администратора](ADMIN_GUIDE.md).

## 10. Завершение работы

Закрытие вкладки браузера не останавливает приложение. Для остановки контейнера администратор должен выполнить команду:

```bash
docker compose down
```

Не удаляйте каталог приложения во время работы контейнера.
